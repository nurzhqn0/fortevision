# ForteVision (ForteBank Datathon 2026)

AI-сервис, который анализирует видеозапись работы кассира, ищет визуально наблюдаемые признаки возможных нарушений кассовой дисциплины и показывает проверяющему тип события, таймкод, кадры-доказательства и ссылку на пункт нормативного акта НБ РК.

Результат сервиса — подсказка для проверки человеком, а не юридическое заключение.

- **UI:** https://nurzhqn--fortevision-fortevisionservice-web.us-east.modal.run/
- **API:** тот же адрес, `POST /api/v1/analyze`, `GET /api/v1/jobs/{job_id}`. Ключ передаётся в заголовке `X-API-Key`; ключ для жюри выдаётся отдельно.
- **Swagger:** `/docs`

---

## Архитектура

```
Браузер / жюри
   │  POST /api/v1/analyze (.mov) ──► job_id
   │  GET  /api/v1/jobs/{id}      ──► processing | done | failed + результат
   │  GET  /api/v1/warmup         ──► заранее поднять GPU-воркер
   ▼
ForteVisionService  (CPU, FastAPI: UI + REST)
   │  spawn(job)                        ▲
   ▼                                    │ запись результата
ForteVisionAnalyzer (GPU A100-80GB, Qwen3-VL-30B-A3B)   modal.Dict "fortevision-jobs"
   1. Кадры: видео семплируется ~1 кадр/с
   2. Вопросы по каждому кадру: модель отвечает «Да/Нет» на 14 коротких вопросов
      (кассир сидит? на столе деньги/личные вещи? рядом с кассиром стоит человек? ...);
      вероятность «Да» берётся из логитов, текст не генерируется
   3. Классификатор: временные признаки по видео → логистическая регрессия (numpy),
      веса подобраны только на открытых обучающих видео (classifier.json)
   4. Локализация: пик сигнала каждого типа нарушения → таймкод и 3 кадра-доказательства;
      модель пишет одно фактическое предложение о кадре; тип → проверенный пункт НБ РК
```

**Почему так, а не «спросить модель, есть ли нарушение».** Проверяли оба подхода на 42 открытых видео. Универсальная VLM, которой показывали подряд все кадры и просили вынести вердикт, ловила 4 нарушения из 22. Те же модели хорошо отвечают на простые вопросы по одному кадру, а вердикт по видео строит небольшой классификатор на этих ответах.

- **Модель:** [Qwen3-VL-30B-A3B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-30B-A3B-Instruct) (Apache-2.0, коммерческое использование разрешено). Работает внутри развёрнутого сервиса, внешние AI API не используются. Звук и распознавание лиц не используются.
- **Переносимость:** веса кешируются в томе `/models`. После первой загрузки модель грузится с `local_files_only=True`, и интернет для обработки видео не нужен. Для переноса в контур банка нужны GPU-хост с ≥80 ГБ VRAM, папка с весами и пакет `fortevision`. Код, привязанный к Modal, находится только в `app.py`.
- **Холодный старт.** Загрузка ~60 ГБ весов занимает несколько минут. Перед проверкой жюри вызовите `GET /api/v1/warmup` (или поставьте `min_containers=1` в `app.py`); воркер держится тёплым 30 минут после последнего запроса.
- **Надёжность:**
  - Тяжёлый анализ идёт в отдельном GPU-контейнере, поэтому веб-часть всегда отвечает на опрос статуса.
  - Любая ошибка модели даёт `status: failed` с текстом ошибки, а не ложный «нарушений нет».
  - Задача, зависшая дольше 450 с, помечается как `failed`.

## Запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e . pytest
pytest tests/ -v                       # юнит-тесты (без GPU, VLM подменяется заглушкой)
modal deploy src/fortevision/app.py    # деплой: выведет публичный URL
# свой ключ: задать FORTEVISION_API_KEY в окружении контейнера (config.py)
```

Оценка на открытом датасете (через API, как это будет делать жюри):

```bash
python scripts/evaluate.py --api-url <URL> --api-key <KEY> --concurrency 3
```

Переобучение классификатора (на Modal):

```bash
modal run --detach scripts/extract_features.py --model Qwen/Qwen3-VL-30B-A3B-Instruct --out feat.json   # FV_GPU=A100-80GB
modal volume get fortevision-models /features/feat.json .
python scripts/fit_classifier.py feat.json --out src/fortevision/classifier.json   # печатает leave-one-out
```

```json
{
  "job_id": "3f2a9c1e",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Передача наличных денег/ценностей в обход передаточного устройства",
      "timecode_sec": 22.0,

      "evidence_frames": [{"timestamp_sec": 22.0, "image_base64": "/9j/4AAQ..."}]

```

- `verdict` принимает значения `violation` / `no_violation`.
- `evidence_frames` содержит 1–3 JPEG-кадра в base64.
- Без верного ключа сервис отвечает 401.

## Нормативная база

Тексты сверены с официальными редакциями на adilet.zan.kz (по состоянию на октябрь 2026).

| Документ | Ссылка |
|---|---|
| Правила осуществления кассовых операций и операций по инкассации банкнот, монет и ценностей в БВУ, утв. постановлением Правления НБ РК от 29.11.2019 **№ 231** | https://adilet.zan.kz/rus/docs/V1900019680 |
| Правила организации охраны и устройства помещений БВУ, утв. постановлением Правления НБ РК от 24.02.2020 **№ 14** (ред. от 24.12.2024 № 88) | https://adilet.zan.kz/rus/docs/V2000020075 |

**Принцип сопоставления.** У каждого типа нарушения в `src/fortevision/regulations.py` есть:
- пункт акта;
- краткое изложение нормы;
- список визуальных признаков.

Признаки подставляются в промпт модели. Модель возвращает `type_key` и описание того, что видно, а сервис добавляет к описанию норму и ссылку. Цепочка «источник → нарушение → кадр» видна в каждом ответе.

## Распознаваемые типы нарушений

| `type_key` | Что видно на видео | Норма |
|---|---|---|
| `cash_unattended` | Кассир ушёл от стола, на столе остались деньги или сумка с ценностями | № 231, п. 20: на столе только деньги текущего клиента, остальные хранятся в запираемых устройствах |
| `cashier_absent` | Кассир встаёт и выходит из кассы | № 231, п. 22: не покидать рабочее место до окончания обслуживания |
| `unauthorized_person` | Второй человек (не клиент напротив) стоит в кассе рядом с кассиром | № 14, п. 8; п. 16 пп. 1): изолированный кассовый узел с запираемой дверью |
| `manual_counting` | Кассир считает купюры руками, не кладёт их в счётную машинку | № 231, п. 9; п. 19 пп. 2): пересчёт с проверкой подлинности на оборудовании |
| `personal_items` | Куртка, личная сумка, напиток или еда на кассовом столе | № 231, п. 12: личные вещи хранятся вне кассового узла |
| `safe_left_open` | Сейф открыт, пока кассира нет у стола | № 231, п. 20 |
| `phone_use` | Смартфон в руках кассира | № 231, п. 12 (каталог; в сигналах локализации не используется) |
| `other` | Событие вне каталога | Ссылка только на документ № 231 с пометкой «требуется проверка человеком» |

Передача денег через стол из рук в руки в этих записях считается нормой (передаточного лотка в кадре нет), поэтому такой тип не включён.

## Качество на открытом датасете

Прогон `scripts/evaluate.py` через публичный API, 42 открытых видео (22 с нарушением, 20 без), октябрь 2026. Подробности в `evaluation_results.json`.

| Метрика | На обучающих видео (через API) | Оценка для новых видео (leave-one-out) |
|---|---|---|
| Точность вердикта | 78.6% (33 / 42) | 71–76% |
| Найдено нарушений | 20 из 22 (recall 90.9%) | 18–20 из 22 |
| Ложные срабатывания | 7 из 20 нормальных видео (precision 74.1%) | 8–9 из 20 |
| Таймкод в пределах ±6 с (для найденных) | 70% (14 / 20) | — |
| Необработанные видео | 0 | — |

- **Как читать цифры.** Классификатор подобран на этих же 42 видео, поэтому первая колонка завышена. Для новых видео ориентируйтесь на вторую колонку: каждое видео оценивалось моделью, обученной на остальных 41.
- **Приоритет — не пропустить нарушение.** Порог выбран так, чтобы пропусков было мало; цена за это — ложные срабатывания на частях нормальных видео.
- **Ещё не измерено:** точность на видео, снятых под другим ракурсом. Выборка из 42 видео мала, погрешность оценки около ±7 п. п.

## Ограничения и известные ошибки

- **Ложные срабатывания.** На ~40% нормальных видео сервис всё равно говорит «возможны нарушения». Типичные причины: кассир открывает сейф или уходит после того, как убрал деньги; клиент заходит и стоит у стола. Результат нужно проверять человеком.
- **Тип нарушения определяется грубо.** Тип выбирается по пику одного из сигналов (кассир ушёл, личные вещи, второй человек, ручной пересчёт, ...), и на близких по виду событиях бывает перепутан (например, «личные вещи» вместо «передача сумки»). Вердикт и таймкод точнее, чем тип.
- **Таймкод.** Берётся с шагом 1 с по пику сигнала. В ~30% найденных случаев он отличается от разметки больше чем на 6 с, чаще когда в видео несколько подозрительных событий.
- **Мало данных.** Классификатор подобран на 42 видео, ответы модели на вопросы тоже неточны, поэтому новые типы нарушений, которых нет в открытом датасете, могут не распознаваться.
- **Сервис не видит невидимого:** суммы, проводки, документы, полномочия человека. Такие случаи помечаются только как «возможное нарушение».
- **Другой ракурс камеры.** Вопросы к модели не привязаны к зонам кадра, поэтому пайплайн не ломается при смене угла, но точность на новом ракурсе отдельно не измерялась и, вероятно, ниже.
- **Холодный старт GPU** (загрузка ~60 ГБ весов) занимает несколько минут и не помещается в лимит 5 минут. Перед проверкой вызовите `GET /api/v1/warmup`. После этого воркер остаётся тёплым 30 минут.
